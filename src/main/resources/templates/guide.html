도메인 연결 가이드

최종 업데이트 2026-07-21

서브도메인 연결은 두 단계입니다. ① GSMHS.xyz에서 서브도메인을 등록하면 DNS는 자동으로 설정됩니다. ② 그리고 사용 중인 호스팅 서비스에도 이 도메인을 알려줘야 합니다. ②를 빼먹으면 404나 인증서 오류가 나요. 이 페이지는 서비스별로 ②를 하는 방법을 정리한 가이드입니다.

어떻게 동작하나요?

GSMHS.xyz는 이름.gsmhs.xyz → 호스팅 주소로 가는 길(CNAME 레코드)만 만들어 줍니다. 호스팅 서비스는 어떤 도메인이 자기한테 들어오는지 모르기 때문에, 호스팅 쪽 설정에서 커스텀 도메인으로 이름.gsmhs.xyz를 등록해야 올바른 사이트를 보여주고 HTTPS 인증서도 발급해 줍니다. 양쪽 모두 설정해야 연결이 완성됩니다.

GitHub Pages

  1. GSMHS.xyz 등록 시 CNAME 대상에 아이디.github.io를 입력합니다. (프로젝트 저장소여도 항상 아이디.github.io입니다 — 예: h4ru1012.github.io)
  2. 사이트가 배포되는 저장소 → Settings → Pages → Custom domain에 이름.gsmhs.xyz를 입력하고 Save를 누릅니다.
  3. DNS check가 통과되면 Enforce HTTPS를 체크하세요. 인증서 발급까지 몇 분 걸릴 수 있습니다.

참고: Save를 누르면 배포 브랜치에 CNAME 파일이 자동으로 생깁니다. 빌드 도구(React, Vite 등)를 쓴다면 이 파일이 배포마다 유지되도록 public/CNAME에 넣어두세요. 사이트가 404라면 Custom domain 칸이 비어 있지 않은지 먼저 확인하세요.

Vercel

  1. GSMHS.xyz 등록 시 CNAME 대상에 cname.vercel-dns.com을 입력합니다.
  2. Vercel 대시보드 → 프로젝트 → Settings → Domains에서 이름.gsmhs.xyz를 추가합니다.
  3. 상태가 Valid Configuration이 되면 HTTPS까지 자동으로 적용됩니다.

404: DEPLOYMENT_NOT_FOUND가 보이면 Vercel에 도메인을 아직 추가하지 않은 것입니다. 2번 단계를 확인하세요.

Netlify

  1. GSMHS.xyz 등록 시 CNAME 대상에 사이트이름.netlify.app을 입력합니다.
  2. Netlify → 사이트 → Domain management → Add a domain에서 이름.gsmhs.xyz를 추가합니다. "이미 이 도메인을 소유하고 있어요" 흐름으로 진행하면 됩니다.
  3. HTTPS(Let's Encrypt)는 자동 발급됩니다.

Cloudflare Pages

  1. GSMHS.xyz 등록 시 CNAME 대상에 프로젝트.pages.dev를 입력합니다.
  2. Cloudflare 대시보드 → Pages 프로젝트 → Custom domains → Set up a custom domain에서 이름.gsmhs.xyz를 추가합니다.
  3. 활성화까지 몇 분 걸릴 수 있습니다.

Render

  1. GSMHS.xyz 등록 시 CNAME 대상에 사이트.onrender.com을 입력합니다.
  2. Render → 서비스 → Settings → Custom Domains에서 이름.gsmhs.xyz를 추가합니다.

Railway

  1. Railway → 서비스 → Settings → Networking → Custom Domain에서 이름.gsmhs.xyz를 추가하면 Railway가 CNAME 대상 값을 보여줍니다.
  2. 그 값을 GSMHS.xyz 등록(또는 수정) 화면의 CNAME 대상에 입력하면 됩니다. (프로젝트마다 값이 달라요)

Firebase Hosting / AWS

Firebase Hosting은 커스텀 도메인 추가 시 소유 확인용 TXT 레코드를 요구하고, AWS Amplify/CloudFront는 인증서(ACM) 검증용 레코드를 요구합니다. 이런 레코드는 GSMHS.xyz에서 직접 등록할 수 없으니, 호스팅이 안내하는 레코드 값을 복사해서 관리자에게 문의해 주세요. 추가해 드립니다.

직접 호스팅(홈서버 등)

CNAME은 도메인 주소만 가리킬 수 있고 IP 주소는 입력할 수 없습니다. 홈서버라면 DDNS 주소(예: myserver.duckdns.org)를 CNAME 대상으로 입력하세요.

문제 해결

  • Error 1014: CNAME Cross-User Banned — Cloudflare 프록시를 거치면서 다른 Cloudflare 계정의 도메인으로 연결될 때 나는 오류입니다. GSMHS.xyz가 만드는 레코드는 프록시 없이(DNS 전용) 동작하므로 정상적으로는 나지 않아요. 이 화면을 봤다면 관리자에게 문의해 주세요. (관리자: Cloudflare 대시보드에서 해당 서브도메인 CNAME의 프록시(주황 구름)를 꺼서 DNS 전용(회색 구름)으로 바꾸면 해결됩니다)
  • 404가 떠요 — 대부분 호스팅 쪽에 커스텀 도메인을 등록하지 않은 경우입니다. 위 가이드의 호스팅 쪽 단계를 확인하세요.
  • "안전하지 않음" / 인증서 경고 — 호스팅이 인증서를 발급하는 중입니다. 보통 몇 분, 길면 1시간 정도 기다렸다가 다시 열어보세요.
  • 등록했는데 접속이 안 돼요 — DNS 반영은 보통 1~5분 걸립니다. 시크릿 창에서 다시 열어보고, 그래도 안 되면 CNAME 대상 오타를 확인하세요.
  • 그 외 해결이 안 되면 관리자에게 문의해 주세요.
